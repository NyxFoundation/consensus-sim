## 人間への問い
C33 の検証の前半 — 一時ディレクトリの複製で `bash scripts/ci.sh` が exit 0 — が、
周回エージェントの実行環境で起動できません(`bash <script>` の起動と作業木外への
`cd` が権限モードに拒否される。周回 1・2 で再現)。後半の「作業木で `npm test` と
`npm run build` が exit 0」と、スクリプトが行う dist の相対参照検査は、この周回で
すべて exit 0 を確認しました。未確認なのは `npm ci` による clean install だけです。

どれを採るか決めてください。

- **(a) 周回環境に許可を与える(推奨)** — `.claude/settings.local.json` の
  `permissions.allow` に `Bash(bash:*)` と `Bash(cd:*)` を足す(いま入っているのは
  WebSearch / WebFetch の 3 件のみ)。周回が自力で clean copy 検査を回せるようになり、
  C33 は次の周回で機械の証拠付きに met になります。コードが変わるたびに自動で
  再検証される点でも、以後の周回の手間が増えません。
- **(b) 人間が手元で回して刻む** — 複製を作って `bash scripts/ci.sh` を実行し、
  結果を `idd resume --note` で台帳に刻む。次の周回がそれを出典に met にします。
  ただし C33 は本来機械検査なので、`package-lock.json` や依存が変わるたびに
  人間の手作業が要ります。
- **(c) IDEAL.md の C33 の検証方法を書き換える** — clean install の確認を周回の
  責任から外し、作業木での `npm test` / `npm run build` / dist の相対参照検査に
  限る(clean install の成否は main への push 時の GitHub Actions で人間が観測する、
  という「前提」の既存の切り分けに合わせる)。周回は自律で回せますが、
  `npm ci` が壊れた状態を周回が検出できなくなります。

決めていただけないと、必須 32 件のうち C33 だけが blocked のまま残り、
realized に到達できません。
