## 観測
IDEAL.md(C1〜C36)・空の台帳(ideal_sha 未投影)・knowledge.md・git log を読み、
前提どおり全条件が実装済みの状態から始まると分かった。ところが `npm test` は
199 件が失敗。jsdom を宣言した UI テスト 11 ファイルが全滅し、原因はすべて
`localStorage` が undefined(`src/ui/scenarioStore.ts` の読み出しで throw)。
Node 26 が自前の `localStorage` グローバルを持ち、vitest 4 の jsdom 環境は
「既にグローバルにある名前」を上書きしないため、jsdom の storage がテストに
届いていない。ドメイン側は 290/291 通過で、残り 1 件は 5 秒の既定タイムアウト超過。

## 選択
台帳が空で、どの条件も検証コマンドが通らなければ met にできない。差分の根は
実装ではなく検証経路そのもの(C33 の「ユニットテストがすべて exit 0」)なので、
まずこれを直せば残り 35 条件の観測が一度に可能になると判断した。

## 変更
- `tests/setup/storage.ts`(新規)— 書き込めない `localStorage` を検出したときだけ
  最小の in-memory Storage をグローバルに差し込む。DOM の無い node 環境のテストには
  触れない。
- `vite.config.ts` — defineConfig を `vitest/config` から取り、`test.setupFiles` に
  上記を登録。あわせて `testTimeout` / `hookTimeout` を 30 秒に(UI テストは 1 本で
  数十スロットの再計算と再描画を回すため既定 5 秒では足りない。判定内容は変えていない)。
- `.idd/progress.md` — C1〜C36 を投影し、ideal_sha を正本に合わせた。
- `.idd/knowledge.md` — 上記の環境事実と、周回環境が拒否する操作を追記。

## 申し送り
- 必須で残るのは C33 だけ。作業木の `npm test` / `npm run build` は exit 0 だが、
  検証の前半「一時ディレクトリの複製で `bash scripts/ci.sh` が exit 0」が周回環境の
  権限で実行できない(`bash …` 起動と作業木外への `cd` が拒否される。`mktemp -d` と
  `cp -R` は通る)。次の周回はまずこの 1 本を試し、同じく拒否されるなら C33 を
  blocked のままにして、人間に (a) 周回環境で `bash scripts/ci.sh` を許すか、
  (b) 人間の手元で clean copy 検査を実行してその結果を刻むか、を ask で問う。
  それ以外に手を入れる差分は無い(残り 35 条件は本周回の証拠付きで met)。
- テストが落ちたときは、まず単独ファイルで再実行して切り分けること。機械の
  load average が数百に跳ねると 30 秒のタイムアウトでも落ちることがある(本周回で
  1 回観測。負荷が引いた後の再実行では 4 回連続で全緑)。
